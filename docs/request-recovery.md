# 重启任务保留与结果补发

默认先保存 OneBot v11/v12 消息任务，再开始模型或工具工作。关停时停止接收新的 LLM 请求，
暂停下一轮模型与工具派发；给在途工作 15 秒完成并保存结果，随后取消等待任务并再给 5 秒清理。
NoneBot 的资源和 HTTP 会话在请求排空之后关闭。第二次退出信号仍交给原服务框架处理。

启动且 Bot 连接后，先处理全部已保存的待发送结果，再继续未完成的模型任务。
会重新核验用户仍在群内、实时角色、当前权限、Matcher 规则以及宿主消息守卫。
已退群、被当前访问规则拒绝的用户不会收到旧结果。恢复提示会真正 @ 原提问者。
服务商配置、系统提示和工具权限使用当前版本；不会恢复旧权限或保存模型凭据。

## 发送与工具边界

- 最终文字、表情与附件先作为一个完整回复包落盘，逐条记录待发送、发送中、已确认或未知状态。
- 必须收到有效 `message_id` 才标记已发送。已确认结果不重发；发送中、取消或丢失回执的消息不自动重发。
- 已完成工具结果继续使用，避免恢复后重复操作。工具执行中断且结果不确定时，仅总结已有结果并提示核对。
  不自动重放绑定、支付、订阅、发送等操作。
- 未开始工具的请求可恢复正常处理。恢复时重新建立模型、工具和消息上下文，使用新的请求预算。
- 持久模式把流式答案缓冲到完整回复后再投递，避免重启后重复发送已显示的半段答案。
- 插件自行调用 Bot API 的发送路径保留回执证据；不伪造成功，不接管插件自身的任意后台任务或重放副作用。
- 临时成员查询失败会保留任务，等待下次连接再核验。一个恢复轮次不会重复处理失败任务，最多尝试三次。
- 恢复仍受现有并发、排队、模型和工具限制影响。这不是任意插件的通用工作流恢复系统。

## 配置

这些字段属于 NoneBot 配置，可写入既有 `.env`，不属于 LLM 的 `config.json`：

| 配置 | 默认值 | 含义 |
| --- | --- | --- |
| `MOELLM_RECOVERY_ENABLED` | `true` | 开启任务检查点和发件箱 |
| `MOELLM_RESTART_GRACE_SECONDS` | `15` | 首次退出信号后的完成等待，0～60 秒 |
| `MOELLM_RESTART_CANCEL_SECONDS` | `5` | 取消后的清理等待，1～15 秒 |
| `MOELLM_RECOVERY_RETENTION_SECONDS` | `86400` | 记录保留时间，默认 24 小时 |
| `MOELLM_RECOVERY_MAX_ENTRIES` | `512` | 最多记录数 |
| `MOELLM_RECOVERY_MAX_BYTES` | `268435456` | 总容量默认 256 MiB |

记录在 LocalStore 数据目录的 `request_recovery/`，包含用户消息、工具结果与待发送附件，属于私有数据。
目录权限 0700、文件 0600，拒绝符号链接，单条最多 32 MiB；一个目录只允许一个进程持有恢复锁。
写入采用临时文件、原子替换与 fsync，磁盘操作在线程中串行执行。容量不足时先回收已完成记录，
实际待处理记录不会为接收新任务被提前删除；仍满则拒绝开始新工作。
超过保留时间的记录在启动时清理，不再恢复；损坏记录保留原文件并跳过，避免阻塞其他正常任务。

独立 NoneBot 部署复用原退出信号处理器。宿主已有退出守卫时，可通过软集成先排空 LLM，
再开始宿主退出步骤。配置的等待时间只约束这部分任务排空；其他插件的关闭钩子仍由宿主管理。
