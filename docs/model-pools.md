# 模型池与额度退池

`model_config.json` 可配置 `model_pools`，把不同服务商的模型放进同一用途的池。
模型名必须是 `模型名 (服务商)` 完整身份，复用 `providers.toml` 中各自的地址、凭据与参数。

```json
{
  "model_pools": {
    "category": ["small (provider-a)", "small (provider-b)"],
    "0": ["small (provider-a)", "small (provider-b)"],
    "1": ["medium (provider-a)", "medium (provider-b)"],
    "2": ["large (provider-a)", "large (provider-b)"]
  }
}
```

- `category`：意图分类、`summary_model` 的工具草稿复核。
- `0`、`1`、`2`：简单、中等、复杂问题；`selected_model` 使用 0 档，群聊总结使用 2 档。
- 新请求按用途分别轮换；已耗尽、缺少密钥、缺少本轮工具或视觉能力的候选会被跳过。
- 一次请求遇到 429 临时限流或明确额度耗尽后，选择同池尚未尝试的模型；保留消息、工具定义与已有结果。
- HTTP 402/403 的明确额度耗尽会把该服务商的该模型持久标记为 `quota_exhausted`。
  普通鉴权、权限与内容拒绝不会触发退池；429 不会永久退池；网络超时也不等于额度耗尽。
- 不自动跨档降级。一档全部不可用时说明原因；分类池不可用时，沿用常驻工具继续回答。
- 没有配置池的功能继续使用原来的单模型及 `model_fallbacks`。
  绘图和多模态使用相同额度识别与标记，仍只选择其显式配置且满足媒体能力的备用。
- 不和 `capability_routing` 同时启用；后者的可信能力目录有独立路由契约。

状态存于 LocalStore 配置目录的 `model_quota_status.json`，仅包含模型身份、原因、HTTP 状态与时间。
它独立于配置快照，避免一次耗尽触发全套资源重载；重启或刷新模型列表不会清除耗尽标记。
这里不推测供应商剩余额度，只有实际明确错误才退池。各供应商的免费额度控制仍由账号控制台执行。

超级管理员可使用：

```text
!查看配置
!查看模型 模型关键词
!恢复模型额度 模型名 (服务商)
```

`查看配置` 显示池成员与可用数量，`查看模型` 标注耗尽状态。确认续费、额度重置后再恢复模型额度。
恢复只清除本地标记，不声称服务商已经补充额度。新增池的 Python 逻辑需要加载新版本后生效。
